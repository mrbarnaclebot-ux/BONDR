In the main thread: grind({ count, threads }) spawns T threads on this same file (new Worker(new URL(import.meta.url))), inserts hits as (idx, pubkey) with on conflict do nothing, and stops after count hits. The start index is max(idx) + 1 for the lane's database, so a restart continues (ponytail: re-scans the gap after the last hit, at most a few minutes; store a next_idx row if that ever matters).
