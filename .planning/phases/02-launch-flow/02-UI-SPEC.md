# Phase 2 — UI Design Contract

> Visual and interaction contract for the Launch Flow phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Source of truth: `.planning/design/DESIGN-BRIEF.md` (round 2) and the approved round 2 mockups in `.planning/mockups/` (`launch.html` steps 1-5, `consent.html`, `token.html` identity bar, `tokens.css`, `mock.js`). ## Spacing Scale

Declared values (multiples of 4), the same as `tokens.css`:

| Token | Value | Tailwind | Usage |
|-------|-------|----------|-------|
| 2xs | 4px | `1` | Icon gaps, tag inner gap |
| xs | 8px | `2` | Field label to input, chip gaps, icon to text in buttons |
| sm | 12px | `3` | Review row padding, callout gap, list item gaps, input vertical padding (see exceptions) |
| md | 16px | `4` | Default element spacing, card inner padding on mobile, receipt row gaps |
| lg | 24px | `6` | Panel gap between fields, receipt padding, consent padding on mobile |
| xl | 32px | `8` | Panel padding on desktop, consent padding, stepper margins |
| 2xl | 48px | `12` | Launch grid column gap, page top padding |
| 3xl | 64px | `16` | Terms page top padding |
| 4xl | 96px | `24` | Footer top margin only (see exceptions) |

Page gutter: `clamp(16px, 3vw, 40px)`. Max content width: 1440px.

Exceptions to the 8-point rhythm (both are multiples of 4 and come from `tokens.css`):

| Value | Justification |
|-------|---------------|
| 12px (sm) | The dense receipt-style lists (review rows, receipt rows, sign rows, callout icon gap, consent list) read as ruled ledgers. 8px crowds the hairline rules and 16px breaks each group into loose islands. 12px is used only inside those lists and for input vertical padding, never between sections |
| 96px (4xl) | Used once: the footer's top margin, the single page-level break between the last content block and the footer. 64px let the footer read as part of the receipt or terms article above it |

Normalizations (the mockups use a few off-scale values; implementation rounds them as listed):

| Mockup value | Implementation | Where |
|--------------|----------------|-------|
| 6px gaps | 8px | field grid gap, chip gap |
| 10px | 12px | consent list gap, input vertical padding. 12px is the nearest multiple of 4 that keeps text centered in the 48px input: 12 + 23px (15px text at 1.55) + 12 + 2px border = 49px, so `min-height: 48px` never clips and the text sits on center. 8px would leave 3px of uneven slack; 16px would push the input to 57px |
| 14px / 18px horizontal padding | 16px | input, default button |
| 42px button min-height | 44px | default button (tap target) |
| 46px input min-height | 48px | text inputs |
| 32px chip min-height | 44px below 768px, 40px at 768px and up | dev buy preset chips (tap target) |
| 28px copy chip min-height | 44px below 768px, 32px at 768px and up | token page mint copy chip (tap target) |
| 34px stepper top padding | 32px | stepper label offset |
| 3px / 9px tag padding | 4px / 8px | tags and the DEVNET badge |

## Typography

Two scales: a UI scale (Schibsted Grotesk and Martian Mono) with exactly 4 sizes and 2 weights, and a display scale (Big Shoulders Display, uppercase, weight 800 only) for headings and stamped numerals. The display face is part of the approved brand and is counted separately.

No display size or display weight is ever used for interface text. Labels, buttons, inputs, hints, errors, tags, receipt rows and body copy use only the 4 UI sizes at 400 or 600. The display scale is only for the headings and numerals listed in its table.

### UI scale

Override Tailwind's defaults in `@theme` so the class names match these sizes (Tailwind's stock `text-sm` is 14px, not 13px).

| Role | Size | Tailwind | Weight | Line height | Used for |
|------|------|----------|--------|-------------|----------|
| Caption | 12px (0.75rem) | `text-xs` | 400; 600 for caps labels | 1.4 | Hints, field errors, character counts, receipt rows, uppercase section labels (`letter-spacing: 0.09em`), tx links, short addresses, DEVNET badge |
| Label | 13px (0.8125rem) | `text-sm` | 600 for field labels and buttons; 400 for prose | 1.5 | Field labels, default buttons, review rows, callouts, consent body, sign-step rows, terms nav |
| Body | 15px (0.9375rem) | `text-base` | 400 | 1.55 (terms article 1.65) | Body copy, lede, exit card titles (600), large buttons (600), proof headline (600) |
| Emphasis | 20px (1.25rem) | `text-lg` | 400 mono / 600 UI | 1.3 | Dev buy amount input (mono), terms section headings (UI 600) |

Weights in the UI scale: 400 and 600 only. Mockup uses of 500 and 700 in the UI face (`b`, `.terms h2`) render at 600.

### Display scale (Big Shoulders Display, uppercase, `letter-spacing: 0.01em`)

| Role | Size | Weight | Line height | Used for |
|------|------|--------|-------------|----------|
| Display | `clamp(2.5rem, 6vw, 4.5rem)` (40-72px) | 800 | 0.92 | "Launch a coin" h1, "{SYMBOL} is live." heading, "Terms" h1. The launch h1 grows from the mockup's 64px cap to 72px at 1200px and up; the lede and stepper below it are unchanged |
| Heading L | 44px (2.75rem) | 800 | 0.95 | Consent heading (desktop), token page name (desktop) |
| Heading M | 28px (1.75rem) | 800 | 1.0 | Receipt coin name, consent heading (below 768px), token page name (below 768px) |
| Stamp | 72px (4.5rem) | 800 | 0.8 | The proof "0" |
| Wordmark | 25.6px (1.6rem) | 800 | 1 | "BONDR" in the header, `letter-spacing: 0.04em` |

Display weight: 800 only. The mockup's 900 for the wordmark and the "0" drops to 800. In Big Shoulders Display the step from 900 to 800 is a slight stroke thinning, and the stamp's accent color, glow and double rule carry its emphasis, so the approved look holds and one font file is saved. Visual check: compare the header and proof stamp against `screenshots/launch-step5-copied-390.png`.

### Mono (Martian Mono, 400, condensed)

Every number, SOL amount, percentage, address, signature, CID, byte count, character count and step index uses mono at the UI size of its context. Never use mono for prose.

The palette is fixed by the owner. Neutrals are tinted toward the brand green. All derived values are the `color-mix(in oklch, ...)` formulas in `tokens.css`; port them unchanged.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#1a1a1a` background, with two fixed radial light leaks (secondary 34% top right, accent 7% left) and the film grain | Page background |
| Secondary (30%) | `surface` (background + 9% `#32712a`), `surface-2` (16%), `surface-3` (28%), panel gradient `surface-2` to `surface` | Panels, receipt, consent dialog, inputs (`ink` 55% + surface), header (background 82% + blur 14px) |
| Accent (10%) | `#56c44a` | Only the elements listed below |

| Brand secondary | `#32712a` | Surface tint, done stepper node fill, connected wallet button (`btn-solid`), done sign-step icon |
| Text | `#ebf3ea` (13.9:1 on background); muted text = text 68% into background (6.6:1) | All text |
| Destructive / error | `#f0705e` (5.9:1 on background) | Field errors, failure callouts, failed sign-step icon. Never decoration |
| Warning | `#e2c56b` | Paused callout icon and border, DEVNET badge |

Accent `#56c44a` is reserved for:
1. Primary CTA fill: "Continue to dev buy", "Review launch", "Sign in Phantom", "Accept and continue", "Open {SYMBOL}"
2. Focus ring (`outline: 2px solid`, offset 2px) and focused input border plus 3px 25% halo
3. Active stepper node (fill, 6px halo, 22px glow) and the done-connector gradient (secondary to accent)
4. Selected exit card: border, radial wash, `--glow` shadow; native radio and checkbox `accent-color`
5. Proof stamp: the "0", its border and outline, its radial wash, and the "Proof, checked on-chain" label
6. The word "live." in the success heading, and the orb ring around the coin avatar on the success art
7. Positive "0" and "80%" values in the receipt ("Launch supply you hold", "BONDR platform fee", "You, permanently") and the insta sell "You get back about" amount
8. "Copied" state on copy buttons, the connected status dot in the consent dialog

Accent is never used for body text, borders of unselected controls, secondary buttons or headings (other than item 6).

## Shape, Elevation, Light and Grain

| Token | Value | Usage |
|-------|-------|-------|
| `--radius-sm` | 8px | Small chips, mockbar-size controls |
| `--radius` | 12px | Inputs, buttons (default and large; the mockup's 14px large radius normalizes to 12px), callouts, exit cards, drop zone |
| `--radius-lg` | 20px | Panels, receipt (bottom corners), consent dialog, proof stamp, CA row |
| sheet | 24px top corners | Consent as a bottom sheet below 768px |
| pill | 9999px | Tags, DEVNET badge, segmented controls |
| `--hi` | `inset 0 1px 0` text 9% | Top highlight on every elevated surface |
| `--elev-1` | `--hi` + 2 green-tinted shadows (see `tokens.css`) | Panels, terms nav |
| `--elev-2` | `--hi` + 3 green-tinted shadows | Receipt, consent dialog |
| `--glow` | 1px accent 45% ring + `0 10px 40px -8px` accent 45% | Selected exit card |

- Body background: the two radial light leaks from `tokens.css` `body`, fixed to the page.
- Film grain: a fixed `body::after` with the inline SVG `feTurbulence` noise from `tokens.css`, `opacity: 0.07`, `mix-blend-mode: overlay`, `pointer-events: none`, `z-index` above content and below dialogs.
- Local glows: the receipt's top radial (accent 9%), the consent dialog's top radial (accent 12%), the proof stamp's left radial (accent 16%) and its `0 18px 50px -24px` accent shadow, the success art's vignette.
- Receipt perforated top edge: the `radial-gradient(circle at 6px -1px, ...) 0 0 / 12px 8px repeat-x` strip from `launch.html`.

## Motion

CSS only. No animation library.

| Token | Value |
|-------|-------|
| `--ease-out` | `cubic-bezier(0.22, 1, 0.36, 1)` |
| `--ease-spring` | `linear(0, 0.08 4%, 0.3 10%, 0.64 20%, 0.88 30%, 1.01 40%, 1.035 48%, 1.02 60%, 1.004 75%, 1)` (one small overshoot, no bounce) |
| `--dur` | 220ms (color, border, background) |

| Element | Motion |
|---------|--------|
| Button hover / press | `translateY(-1px)` with 420ms spring; press `translateY(1px) scale(0.99)` at 80ms |
| Exit card hover | `translateY(-2px)` 500ms spring (not on the disabled Streamflow card) |
| Step panel enter | `rise` (opacity 0 to 1, `translateY(14px) scale(0.985)` to none) 420ms `--ease-out` |
| Stepper node | background 500ms spring, active node `scale(1.15)` 500ms spring; connector fill 600ms `--ease-out` |
| Consent dialog | `rise` 620ms spring; bottom sheet below 768px rises from the bottom edge |
| Sign step "now" | Ring spinner, 900ms linear, infinite |
| Success art | Three orb rings, 2.8s `--ease-out`, staggered 0.9s, infinite |
| "Copy address" button | Label "Copy address" to "Copied" for 1600ms, then back |
| Brand mark hover | `rotate(-12deg) scale(1.05)` 600ms spring |
| Token page bleed | 18s `drift` alternate on the blurred avatar copy |

`prefers-reduced-motion: reduce`:
- The global override from `tokens.css` applies (all animations and transitions 1ms, one iteration).
- Orb rings are hidden; the avatar keeps its static accent ring and glow.
- The sign-step spinner becomes a static accent ring with a filled quarter. The row's small text still says what is happening, so progress does not depend on motion.
- The token page bleed stops.
- Nothing auto-scrolls; focus moves without smooth scrolling.

## Interaction and State Contract

### Wallet control (header)

| State | Visual | Behaviour |
|-------|--------|-----------|
| Disconnected | Quiet button, wallet icon, "Connect Phantom" | Click calls Phantom `connect()` |
| Connecting | Same button, disabled, "Opening Phantom…" | Returns to Disconnected if the user closes Phantom, with no error message |
| Connected | Solid (forest) button, short address `9wRt…e3Fk` in mono | Click opens the wallet menu: "Copy address", "Disconnect" |
| Phantom not installed (desktop) | Popover under the button | Text plus "Get Phantom" link (phantom.com/download, new tab) |
| Phantom not installed (mobile browser) | Same popover | Primary "Open BONDR in Phantom" (Phantom browse deep link to the current URL) and secondary "Get Phantom" |
| Account switched in Phantom | Connected button shows the new address | Consent is re-checked for the new address. A launch in step 4 before submit is cancelled with the account-switch error |

Connect then consent: after `connect()`, the browser reads its consent session (a cookie; the request carries no address). If the session is not for this address, the consent dialog opens. Nothing about the wallet is sent to the server before Accept. (Owner decision 2026-10-22, CR-01: sign once at consent.)

### Consent dialog

| State | Behaviour |
|-------|-----------|
| Open | Modal; focus starts on the checkbox; "Accept and continue" disabled until the checkbox is ticked |
| Accepting | Accept button shows "Saving…" and is disabled; Phantom asks to sign the consent message (signMessage: no transaction, no fee) |

- axe-core reports 0 violations at 390, 768 and 1440 for: `/launch` on each of steps 1-5, step 2 with errors, step 4 rejected, the paused state, the consent dialog open, `/terms`, `/coin/[mint]` and its not-found page.
