## Phase Goal

**As a** trader, **I want to** see live lists and charts of every BONDR coin, **so that** I can find and judge coins.

<objective>
The first slice through the stack below the UI: a landed launch becomes a coin row plus its Launch trades in Postgres, through the same idempotent ingest path every later trade uses. Phase 2's existing launches are backfilled at boot so staging has coins to show.

Purpose: every list, card, chart and feed reads these two tables.
Output: coins and trades tables with migration 0003 applied to the dev branch, contract types in api.ts, worker ingest and BONDR price modules, the settle hook and the boot backfill.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-04-01 | Tampering | duplicate or replayed ingest | mitigate | (signature, ix) primary key with on conflict do nothing; coin patches only for inserted rows |
| T-03-04-02 | Tampering | inconsistent rows | mitigate | Database checks: venue enum, side enum, burn implies null sol, curve iff not bonded, progress 0..1, foreign keys to coins, launches and vanity_mints |
| T-03-04-03 | Denial of service | Neon budget | mitigate | Writes only on landed launches and trades; BONDR price in memory; no timers (rg gate) |
| T-03-04-04 | Denial of service | Helius rate limit during backfill | mitigate | pace() between fetches, one-time boot pass over unindexed launches only |
| T-03-04-05 | Information disclosure | logs | mitigate | All errors through redact() |
</threat_model>
