## Phase Goal

**As a** holder, **I want to** see every fee movement with a transaction link, **so that** I can verify none went to the dev.

<objective>
Wire the engine into the worker behind `FEE_ENGINE`: boot recovery, the per-coin queue, window timers that run collect, split and sweep, the trade hook that keeps fee state in memory, the cost written on every curve patch, and the `fee` event to open pages.

Output: fee-recover.ts, fee-engine.ts (+ tests), env, main, ingest split into announce.ts, build.ts floor import, env example and READMEs.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| indexer -> engine | Trade and bond events drive money jobs |
| worker env -> engine | FEE_ENGINE decides whether funds move |
| worker -> web (SSE) | Landed rows fan out to public pages |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-05-01 | Tampering | double send across a restart | mitigate | recover settles every pending row before ready; jobs enqueue only when ready; unique indexes refuse a second intent |
| T-05-05-02 | Elevation of privilege | engine signing for a coin it does not own | mitigate | derived W must equal launches.w, else the coin is skipped (seeded fakes, other lanes) |
| T-05-05-03 | Denial of service | Neon wakes | mitigate | one boot read; timers and hooks use memory only (D-03); cost rides the existing patch write |
| T-05-05-04 | Tampering | engine on by accident | mitigate | FEE_ENGINE defaults to off and refuses unknown values; dry writes nothing (asserted by row counts) |
| T-05-05-05 | Information disclosure | internal rows on the stream | mitigate | publishFee filters to landed PUBLIC_KINDS before publish |
| T-05-05-06 | Repudiation | shared devnet ops and buyback across lanes | mitigate | buyback derives per lane; ops is shared by design and stays off locally except for the e2e (Pitfall 11) |
</threat_model>
