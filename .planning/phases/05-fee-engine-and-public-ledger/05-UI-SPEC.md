## Values and data rules

- **SOL equivalents everywhere (D-04).** Every money figure leads with SOL. Raw amounts of the mint moved (BONDR or the coin) appear in prose and sub-lines, so a holder can match them against Solscan.
- **Ledger rows** show the SOL value stored on the row (the value at that moment). They never revalue at today's price.
- **Live panel figures** (budget, cost to complete, "In burn budget") are valued at the BONDR price of the coin's latest indexed trade, the same price `bondSol` and `mcapSol` use, written by the worker on the coin row (D-23). The web does no price math.
- **Ratio** = budget / cost to complete, computed from BONDR base units, never from the SOL values. Displayed floored to 1 decimal ("104.9%" never rounds up to "105.0%"). The budget is the same number the D-10 trigger uses: W's BONDR budget plus 90% of the uncollected creator fees.
- **Totals partition the fees (mockup).** Pre-bond: In burn budget + To buyback + To treasury account for every collected BONDR. Post-bond: Bond burn buy + To buyback + To treasury + Deployer earned.
- **Window** (D-10, D-12): window n closes at `windowStart + windowMs`. `windowStart` comes from the coin row (D-23). `windowMs` is the same `FEE_WINDOW_MS` the worker uses (default 24h; shortened only for local e2e). n = floor((windowStart − launchedAt) / windowMs) + 1. If the client clock passes the close, it rolls forward by `windowMs` and n + 1 (the sweep row arrives over the stream).
- **Only landed rows are public (D-22).** `pending`, `failed`, `expired`, `held`, `buyback_burn` (platform) and `reconcile_diff` rows never render on a coin page.
- **Live (D-22).** A new `fee` event on the existing SSE stream carries the landed row and the coin's updated panel fields. Trade events already carry the coin's live fields, which gain the budget fields. No new reads, no timers that read.
