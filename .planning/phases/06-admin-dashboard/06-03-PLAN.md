## Phase Goal

**As a** platform owner, **I want to** see and fix every coin and job from one dashboard, **so that** nothing needs a manual script.

<objective>
The first clickable slice: the owner opens /admin, connects Phantom, signs one message and lands in the console shell with a 30-minute session. Any other wallet, a public session cookie or a cross-origin call is refused.

Purpose: ADMIN-01's session half. Everything later in the phase sits behind this cookie, so it is built and tested first, reusing session.ts's seal and the consent nonce table (D-09: one more auth shape would be a second source of truth).
Output: session.ts admin helpers with tests, the session route, the guarded [op] forwarder, the page, the sign-in card and the console shell; admin-signin.e2e.ts green.
</objective>

Contract this plan creates:
- `adminWalletEnv(): string | null` (ADMIN_WALLET trimmed, valid BASE58_KEY decoding to 32 bytes, else null).
- `adminMessage(wallet, nonce, expires)` = lines "BONDR admin sign-in", "", "Wallet: {wallet}", "Nonce: {nonce}", "Expires: {expires}", "", "Signing this message is not a transaction and costs nothing." (RESEARCH Code Example 1).
- `adminCookie(wallet, now) -> { header, exp }`, `adminSession(cookieHeader, admin, now) -> { wallet, exp } | null`, `verifyAdmin(wallet, nonce, signature, now) -> Date | null`, `adminSignOutCookie()` (Max-Age=0).
- POST /api/admin/session: `{ op: "nonce", wallet }` -> `{ nonce, expires, message }`; `{ op: "verify", wallet, nonce, signature }` -> `{ wallet, exp }` plus Set-Cookie, or 403 `{ error: "not_admin" }`, 403 `{ error: "not_configured" }`, 401 `{ error: "bad_signature" }`; `{ op: "signout" }` -> 200 plus the clearing cookie.
- POST /api/admin/[op]: 403 (empty) cross-origin; 401 `{ error: "unauthorized" }` without a valid admin cookie; 429 via rateLimited; then `OPS: Record<string, (body, session) => Promise<Response>>` (empty here) and 404 `{ error: "not_found" }` for an unknown op. Later plans add entries; the actor forwarded to the worker always comes from the cookie, never the body.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-03-01 | Elevation of privilege | public bondr_session value replayed as bondr_admin | mitigate | tagged sealed value plus 30-minute cap in adminSession; session.test.ts refuses the public value (Pitfall 1) |
| T-06-03-02 | Spoofing | consent signature replayed as an admin sign-in | mitigate | distinct first line "BONDR admin sign-in"; verifyAdmin test refuses a consent-message signature |
| T-06-03-03 | Spoofing | nonce replay | mitigate | nonce spent once in consent_nonces with onConflictDoNothing().returning(); a replay answers 401 |
| T-06-03-04 | Tampering | CSRF on admin POSTs | mitigate | sameOrigin first, SameSite=Strict cookie, POST only (Pitfall 8) |
| T-06-03-05 | Information disclosure | console probing | mitigate | noindex, unlinked, 401 before any data, rate limits per IP and wallet |
| T-06-03-06 | Elevation of privilege | admin enabled by accident | mitigate | ADMIN_WALLET unset or invalid fails closed with "Admin is not configured" (D-08); adminWalletEnv test |
| T-06-03-07 | Denial of service | sign-in spam | mitigate | rateLimited 10 per 10 minutes before the body is read |
