Contract this plan creates:
- `type Intent = { id; action: AdminTxAction; mint: string | null; message: string; expiresAt: number; used: boolean; state: "simulated" | "sending" | "landed" | "failed" | "unknown" | "refused"; sigs: string[]; landed: number; total: number; code?: string; data: unknown }` (data holds the simulation summary and the allowlist for 06-13).
- `INTENT_TTL_MS = 120_000` (expiry while unused), `INTENT_KEEP_MS = 600_000` (kept after execute for the browser poll), `INTENT_MAX = 200`.
- `intentMessage({ action, coin, id, to, expiresAt }): string` lines "BONDR admin action", "", "Action: {action}", "Coin: {coin ?? 'platform'}", "Intent: {id}", "Destinations: {to joined by ', ' or 'burn only'}", "Expires: {ISO}", "", "This is not a transaction. The BONDR worker checks it before sending."
- `putIntent(fields, now): Intent`, `take(id, sig: Uint8Array, admin: string, now): Intent`, `viewIntent(id, now): AdminIntentView | null`, `updateIntent(id, patch, now)`.
- `type Allowed = { owners: Map<string, string>; atas: Map<string, string>; closeTo: string; mints: string[] }` (address to display name, for example "Treasury", "Buyback", "Deployer 7xKX...", "W 9fQ2...").
- `allowFor({ treasury?, buyback?, deployer?, internal: PublicKey[], mints: PublicKey[], closeTo: PublicKey }): Allowed` computing each owner's ATA for every mint under both TOKEN_2022 and the legacy token program.
- `refusedDestination(ixs: TransactionInstruction[], allowed: Allowed): string | null` returns the refused recipient address, or null.
- `passedLines(allowed): string[]` (for "Destinations check passed: ...").

  <behavior>
    Intent store (admin-intent.test.ts):
    - intentMessage includes "BONDR admin action", the action, the coin mint or "platform", the intent id, each destination name and the ISO expiry; two intents differing only in coin produce different text
    - take with the admin key's signature over the stored message returns the intent and marks it used; a second take answers intent_used (409)
    - take with another key's signature answers bad_intent_signature (403) and the intent stays usable: the admin's take afterwards succeeds
    - take with the admin key's signature over a text that differs by one character (tampered coin) answers bad_intent_signature
    - take at now >= expiresAt answers intent_expired (410); an unknown id answers intent_expired
    - after execute (state sending) the entry survives until INTENT_KEEP_MS for viewIntent; an unused entry is swept after INTENT_TTL_MS; the store never exceeds INTENT_MAX (oldest dropped)
    - a consent message or an admin sign-in message signed by the admin key is refused by take (domain separation)
    Destination check (admin-dest.test.ts):
    - a System Transfer to the treasury passes; to an unknown key it returns that key
    - a Token-2022 TransferChecked to the treasury's BONDR ATA passes; to the deployer's ATA passes only when the deployer is allowed; to an unknown owner's ATA returns that ATA
    - a legacy Token Transfer to an allowed ATA passes
    - BurnChecked and Burn always pass; CloseAccount to the treasury passes and to any other destination returns it
    - ATA create and createIdempotent, ComputeBudget and pump, pump-amm and pump-fees program instructions pass (program flows are covered by the signTx program allowlist)
    - an instruction from an unknown program is not a recipient check and passes here (signTx's ALLOWED_PROGRAMS refuses it at signing; a comment says so)
    - passedLines for a finalize allowlist reads "deployer matches the launch signer" and "treasury matches config"
  </behavior>
  <implementation>
    admin-intent.ts copies trade-store.ts's shape (ponytail header: per-process store, one worker replica, D-03; sweep on insert; cap INTENT_MAX), with ids from randomBytes(16) hex. take follows RESEARCH Code Example 2 exactly: look up, refuse expired or unknown with intent_expired, refuse used with intent_used, verify with signatureOk(Buffer.from(e.message, "utf8"), sig, admin), and only then set e.used = true, with no await anywhere in the function so two concurrent executes cannot both pass; an invalid signature never marks the intent used (no denial of service by a token holder). Expiry is enforced only while unused; once used, INTENT_KEEP_MS governs retention for viewIntent. viewIntent maps to AdminIntentView (no message, no data). admin-dest.ts is pure (no RPC, no env): decode each instruction by program id per RESEARCH Pattern 5 (System Transfer recipient keys[1]; spl-token decodeInstruction in try/catch: TransferChecked destination keys[2], Transfer keys[1], CloseAccount destination keys[1] must equal closeTo; Burn and BurnChecked pass; ATA program and ComputeBudget pass). Add a `ponytail:` comment: the check covers BONDR-authored top-level transfers; CPI recipients inside pump programs are trusted through ALLOWED_PROGRAMS; upgrade path is diffing every writable account in the simulation against the allowlist. Commits: test (RED, both files failing), feat (GREEN), refactor if needed; every function under 40 lines, files under 300 lines.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-05-01 | Elevation of privilege | leaked WORKER_TOKEN executes a money action | mitigate | take verifies the owner's signature over the worker's stored text against ADMIN_WALLET (D-12); admin-intent.test.ts wrong-key case |
| T-06-05-02 | Tampering | intent text altered or replayed | mitigate | message bound to action, coin, id, destinations and expiry; single use set synchronously; tampered-text and second-take tests |
| T-06-05-03 | Spoofing | consent or sign-in signature reused as an intent | mitigate | distinct first line "BONDR admin action"; domain-separation test |
| T-06-05-04 | Denial of service | attacker burns the owner's intent with bad signatures | mitigate | invalid signatures never mark used; test asserts the admin's later take succeeds |
| T-06-05-05 | Elevation of privilege | funds sent to an attacker address | mitigate | refusedDestination over every top-level transfer and CloseAccount; table tests; program flows covered by ALLOWED_PROGRAMS (ponytail comment names the CPI ceiling) |
| T-06-05-06 | Denial of service | memory growth from simulate spam | mitigate | INTENT_MAX cap with oldest dropped, plus web rate limits (06-03) |
