Contract this plan creates:
- `leftoverBurnJob(d, coin): Promise<Landed>` (DONE when W holds 0 child tokens).
- `closeAccountsJob(d, coin): Promise<Landed>` (CloseAccount for each of W's BONDR and child ATAs that exist with a 0 balance, destination d.treasury, signer coin.w; DONE when none; rows: [] because closing moves only rent, which the admin audit records).
- Both LedgerStore.insertPending implementations return [] for an empty rows array without touching the database, so a job with no ledger row (close accounts here, Run migrate in 06-11) sends through land unchanged. Today pgInsert would call drizzle's insert with an empty values list, which throws, and land's `if (!rows)` treats [] as inserted, which is the wanted path.
- `sweepLeftoversJob(d, coin): Promise<Landed[]>` = the closing sweep at the lowest window index at or after the current one with no live sweep row (A9), then leftoverBurnJob, then closeAccountsJob.
- `distributeJob(d, coin, o?: { anyAmount?: boolean })`: with anyAmount, worthPaying's minimum is skipped but pending must still be above 0.
