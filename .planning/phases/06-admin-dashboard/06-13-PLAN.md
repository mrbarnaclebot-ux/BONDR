Purpose: ADMIN-01's fresh signature, ADMIN-04's simulation and destination lock, and ADMIN-10's audit for every transaction action.
Output: admin-money.ts with tests; three gated routes.
</objective>

Contract this plan creates (06-15, 06-18, 06-22 use it verbatim):
- `type MoneyCtx = { deps: FeeDeps; engine: Engine | null; audit: AuditStore; admin: string | null; now?: () => number }` (admin injectable so the fork stage passes its test key).
- `simulateAction(ctx, { actor, action, mint }): Promise<AdminSimResult>`; 409 `{ error: "not_applicable", reason }` when applies() refuses.
- `executeAction(ctx, { actor, id, signature }): Promise<{ id: string }>` answers 202 at once after take, re-check and the pending audit insert; the run continues in the background and updates the intent.
- `intentView(id): AdminIntentView` (404 not_found when unknown).
- `gatedDeps(base, allowed, onRefused): FeeDeps` (allowed always true for switches and holds; land refuses any job whose instructions fail refusedDestination and returns the skipped Landed state so settled() stops later steps).
- Routes: POST /admin/simulate `{ actor, action, mint }`, POST /admin/execute `{ actor, id, signature }` (signature base64 of the 64-byte ed25519 signature over the intent message bytes), POST /admin/intent `{ actor, id }`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| web -> worker /admin/execute | Bearer token plus actor; not trusted alone to move funds |
| owner wallet -> worker | The intent signature is the only authority for a send |
| worker -> chain | Real transactions signed with derived keys |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-13-01 | Spoofing | leaked WORKER_TOKEN replaying execute | mitigate | take verifies an ed25519 signature over the stored message against ADMIN_WALLET in the worker; single use; 2-minute expiry (D-12); tests |
| T-06-13-02 | Elevation of privilege | funds sent to an attacker address through a crafted action | mitigate | allowlist from the coin's own records only (deployer = launches.wallet, D-15); checked at simulate and again inside gated land before each send (D-14) |
| T-06-13-03 | Repudiation | a send with no record | mitigate | pending audit row inserted before the first send, one guarded settle (D-33); call-order test |
| T-06-13-04 | Information disclosure | secrets in audit params or logs | mitigate | params hold the intent id only; no logging of signatures or messages; grep acceptance |
| T-06-13-05 | Tampering | state drift between simulate and execute | mitigate | applies() re-checked at execute; RPC preflight on every send; later steps marked estimated (OQ1) |
| T-06-13-06 | Denial of service | duplicate sends after an unknown result | mitigate | nothing resent automatically; unknown settles failed "unconfirmed" and the owner refreshes (D-12) |
</threat_model>
