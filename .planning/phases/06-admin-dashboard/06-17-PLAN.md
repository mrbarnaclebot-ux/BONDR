Contract this plan creates (06-18 uses it verbatim):
- `type Step = { key: string; title: string; state: "done" | "stuck" | "held" | "next"; at: string | null; detail: string | null; sig: string | null }`.
- `coinTimeline(mint): Promise<{ launch; rows }>` (one launch row plus that mint's fee_ledger rows, newest last).
- `timelineSteps(t, row: WRow, mem, live: AdminCoinLive | null, now, windowMs): Step[]`.
- In apps/web/lib/admin-applies.ts: `type ActionKey = AdminTxAction | "hold" | "release_hold" | "recheck_launch"`; `actionStates({ row, state, live, timeline, balances }): Record<Exclude<ActionKey, "evacuate">, { applies: boolean; reason: string }>` (mirrors the worker's applies; the worker re-checks).
- `ACTION_COPY: Record<ActionKey, { label: string; reason: string; tx: boolean; permanent: string | null }>` in admin-copy-actions.ts, with actResultCopy and stuckErrorCopy.
- Split fixed up front for the 300-line rule: lib admin-timeline.ts (coinTimeline, timelineSteps), admin-applies.ts (ActionKey, actionStates), admin-copy-actions.ts (copy); components admin-timeline.tsx (panel, steps list, live line, the act POST passed down as onAct), admin-timeline-boxes.tsx (StuckBox, HeldBox), admin-action-grid.tsx (ActionGrid and the hint line).
- LOCAL op `coin` `{ mint }` -> `{ timeline, live }` (live null when the worker did not answer).
- AdminTimeline props include an optional `onTx(action: AdminTxAction): void`; transaction buttons render only when it is provided (06-18 provides it).

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-17-01 | Tampering | forged hold or release | mitigate | cookie, sameOrigin and rate limit at the web; gated actor check and one landed audit row in the worker (06-10) |
| T-06-17-02 | Information disclosure | raw RPC or program error text in the stuck box | mitigate | stuckErrorCopy maps codes to contract copy with a generic fallback; test |
