# Phase 7 — UI Design Contract

> Visual and interaction contract for the small Phase 7 UI surface. It covers the launch page in genesis mode (the public banner and the owner's genesis launch variant), the contract check pause reason, the Sender tip line in the launch summary, the "Sniped" line on the token page, the admin "Pump contract check" health cell, the child-launch callouts in the admin Kill switches panel, and the terms page contact and network sentence. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> This spec extends `06-UI-SPEC.md` (approved), which extends 05, 04, 03 and 02. Every earlier token, type role, color rule, component, motion rule and accessibility rule still applies and is not repeated here. Locked decisions come from `07-CONTEXT.md` D-01 to D-39. Rows marked "owner-delegated (auto)" were chosen under the owner's auto-mode instruction (2026-10-26). Each takes the CONTEXT choice, or the existing pattern in the code where CONTEXT is silent. Nothing in this spec commits real money. The Sender tip amount is OWNER GATE G-6, so the UI only displays what the worker reports and never hardcodes it.

### 1. Launch page: pause reasons and the genesis banner (D-22, D-29)

File: `apps/web/components/launch-flow.tsx`, the `PAUSED` map and the always-mounted `aria-live="polite"` wrapper around the warn `Callout`. Type: `PauseReason` in `packages/core/src/api.ts` gains `"genesis"` and `"contract_check"`.

| Reason | Callout variant | Title | Body |
|--------|-----------------|-------|------|
| `genesis` (public, or owner without an admin session) | warn | "Launches are not open yet." | "Launches open after the BONDR token is live. You can fill this in now; the Launch button unlocks automatically when launches open." |
| `contract_check` | warn | "Launches are paused." | "A weekly safety check found that pump.fun changed something BONDR depends on, so new launches are paused while the owner reviews it. ### 3. Launch summary: Sender tip row (D-34, LAUNCH-08; amount is OWNER GATE G-6)

File: `apps/web/components/launch-receipt.tsx`, the `now` rows. Type: `Status` in `packages/core/src/api.ts` gains `senderTipEstimate: string | null` (lamports; `null` off mainnet), filled by `apps/worker/src/status.ts` from the same value `fee-send.ts` `tipIxs` uses. Owner-delegated (auto): a separate row rather than folding the tip into "Network fee", so a creator sees what the tip costs and the G-6 amount stays visible.

| Net / state | Row |
|-------------|-----|
| Mainnet, status loaded | "Sender tip" / `cost(senderTipEstimate)`, which renders "about {sol} SOL" (existing `cost()` helper, rounded up) |
| Mainnet, first status loading | "Sender tip" / "…" (existing `gap`) |
| Mainnet, status read failed | "Sender tip" / "Unavailable" (existing `gap`, muted sans) |
| Devnet and fork (`senderTipEstimate === null` with a loaded status) | Row not rendered |

Row order in "You pay now": "Dev buy", "Pump create and accounts", "Network fee", "Sender tip", "Back to you on insta sell".

The step 2 balance check (`launch-buy.tsx` line 34, the sum of dev buy, create cost and network fee) adds `senderTipEstimate` when present, so the existing insufficient-balance copy stays correct.

### 4. Token page: Sniped line (D-35, D-36)

File: `apps/web/app/coin/[mint]/page.tsx`, inside the `CoinIdentity` children, directly under `ProofStamp`. The value comes from the coin row (`coinByMint` in `apps/web/lib/coins.ts`) as an integer bps field, server-rendered at page load.

Layout: wrap `ProofStamp` and the line in `<div className="grid max-w-[460px] gap-4">`. The 16px gap clears the stamp's 1px outline at 4px offset. The line is a `<p>` with `pl-4` (16px, aligned with the stamp's inner left padding), Caption (`text-xs`), `text-muted-foreground`. It is not inside the stamp: the stamp is the leaf proof, and this line is a disclosure.

Copy (D-36, verbatim second and third sentences):

> **Sniped {pct} of supply.** BONDR cannot stop third-party buys at launch. This shows how much was bought in the first 3 slots.

- "Sniped {pct} of supply." is `font-semibold text-foreground`, with `{pct}` in `num`. `{pct}` is `pct(bps, true)` from `apps/web/lib/format.ts` ("3.2%", "0%", "41%").
- The worker rounds the figure up to the next whole bps, so any third-party buy in the window never reads "0%" (owner-delegated (auto)).

| State | Rendered |
|-------|----------|
| Create slot recorded, bps 0 | "Sniped 0% of supply. BONDR cannot stop third-party buys at launch. This shows how much was bought in the first 3 slots." |
| Create slot recorded, bps above 0 | Same template with the figure |
| No create slot (coins launched before Phase 7, or a landing not settled yet) | Line not rendered |
| Coin row read failed (`coin` null) | Line not rendered |

Forbidden copy anywhere in the product: "sniper-proof", "anti-snipe", "snipe protection", "no snipers", "fair launch guaranteed", or any wording that implies BONDR prevents or limits sniping. The figure is never colored leaf, warn or destructive, and it carries no good or bad judgment.

ponytail: the line is read at page load, not streamed. The figure settles within seconds of launch, and a reload shows the latest. Stream it only if the owner asks.

### 5. Admin Health: Pump contract check cell (D-18 to D-21)

Files: `apps/web/components/admin-health.tsx` (one more `HealthCell`), `apps/web/lib/admin-copy-health.ts` (new pure `contractCopy()` returning the existing `Cell` type, plus cases in `admin-copy-health.test.ts`). Data: `AdminHealth` in `packages/core/src/api-admin.ts` gains a `contract` field from worker memory, delivered by the existing 10s visibility-aware health poll. No Postgres read.

Placement: last cell, as in the mockup (`admin.html:147`), with `md:col-span-2` so the failed-fact list has the full panel width. Label "Pump contract check". Same cell anatomy as every health cell (caps Caption label, Label mono value, Caption muted sub-line, `py-3`, 1px `line` rule).

| State | Value (tone) | Dot | Sub-line |
|-------|--------------|-----|----------|
| Worker not answering or no poll yet | "–" (muted) | none | none (the existing `DASH` cell) |
| Not run since boot | "Not run since boot" (muted) | none | "Program IDs, IDL layouts, Global flags. Runs at boot and weekly." |
| Running | "Checking…" (muted) | none | "Program IDs, IDL layouts, Global flags. Runs at boot and weekly." |
| Passed | "Passed {time}" (ok, leaf) | none | "Program IDs, IDL layouts, Global flags. Runs at boot and weekly." |
| Passed, a programdata deploy slot changed | "Passed, pump redeployed" (warn) | none | "{programs} redeployed since the last check. Every fact still passes; nothing was paused. Checked {time}." |
| Mismatch | "Mismatch, jobs paused" (danger) | static 8px `bg-destructive` | "{facts}. Checked {time}. Every job was paused. Turn them back on one at a time after review." |
| Could not run (RPC error, no facts read) | "Could not run" (warn) | none | "The RPC did not answer. Last pass {time}." or, with no pass since boot, "The RPC did not answer." |

- `{time}` uses the existing `auditTime()` from `apps/web/lib/admin-copy-audit.ts` ("14:02:11" today, "Yesterday 06:00", else "Oct 19 06:00"). No new date helper.
- `{programs}` joins the changed program names: "pump", "pump AMM", "pump fees" ("pump and pump AMM redeployed…").
- `{facts}` is the worker's list joined with "; ", shown in full and wrapping (`[overflow-wrap:anywhere]`). The worker writes facts in plain words. It reuses the existing drift strings from `scripts/spike/stages/config.ts` verbatim (for example "creator fee not configurable, assumed 150 bps per coin", "curve protocol 100 bps, assumed 95", "maxCurveDepth 0, need 1") and adds these templates:
  - "{program} program missing or not executable"
  - "{program} program not owned by the upgradeable loader"
  - "{account} account is {got} bytes, expected {want}"
  - "{account} discriminator changed"
  - "{account} no longer decodes with the pinned SDK"
  - "create_v2 disabled"
  - "creator fee not configurable" (mainnet and fork profile; the devnet profile expects false, D-19)
- "Could not run" does not pause anything (owner-delegated (auto): no fact was read, so there is no mismatch). The planner confirms this in the worker. The next scheduled run or "Run check now" retries.

**Run check now** (the D-18 on-demand route): a link-style button in the cell, under the sub-line, styled like the existing `StuckLine` button (`min-h-11 md:min-h-6`, Caption, mint, underline).

| State | Button | Line under it |
|-------|--------|---------------|
| Idle | "Run check now" | none |
| In flight | "Checking…" (`aria-disabled`, `aria-busy`) | none |
| Answered | "Run check now" | none; the cell shows the result from the response at once, then from the next poll |
| Request failed | "Run check now" | `role="alert"` Caption destructive: "Could not run the check. Try again." |
| 401 | n/a | the existing `onUnauthorized()` swap to the sign-in card |

It sends no transaction, so it has no simulation dialog and no fresh signature. It is not rendered while the worker is not answering.

## Accessibility Contract

- The launch banner wrapper stays always mounted with `aria-live="polite"`, so a contract-check pause that starts mid-session is announced.
- The genesis Sell card uses a native `disabled` radio with its reason as visible text inside the card (the existing Streamflow pattern).
- Health cells stay non-live (06 rule). The "Run check now" error line is `role="alert"`. The mismatch callout is an error `Callout` (`role="alert"`), mounted once per state change rather than re-rendered on every poll with new text.
- The mismatch dot is `aria-hidden`; the value word carries the state.
- "Run check now" is at least 44px tall below 768px and 24px from 768px. The mailto and `/launch` and `/admin` links follow the global `a` style and focus ring.
- The Sniped line is plain text in reading order after the proof. No icon, no tooltip.
- axe-core reports 0 violations at 390, 768 and 1440 for: `/launch` with the `genesis` and `contract_check` banners; `/launch` owner genesis variant on steps 2 and 3; `/coin/[mint]` with the Sniped line; `/admin` with the contract cell passed, mismatch (with the callout) and could-not-run; `/terms`.

## Addendum: anti-vamp ticker cooldown (D-40 to D-44, added 2026-10-26)

Extends the contract above for the ticker cooldown, the reserved list and the search marker. Every choice here is owner-delegated (auto). No new tokens, components, icons or dependencies. Sources: `07-CONTEXT.md` D-40 to D-44, `07-RESEARCH.md` Pattern 12 and Pitfalls 22 to 24.

### A1. Launch refusal: `ticker_locked` (D-40, D-42, D-43)

Renders in the existing step 4 error `Callout` (`components/launch-sign.tsx`, `FAULTS` and the `fail()` path), `action: null` (a retry would be refused again). `FAULTS.text` is static, so the two ticker entries take their text from a new pure `tickerFault(code, symbol, err)` in `apps/web/lib/ticker-copy.ts`, with one runnable check `ticker-copy.test.ts` covering every row below. `{t}` is `"$" + symbol`, using the `checkSymbol` value from step 1 (uppercase, as stored). The worker must tell a landed lock from an in-flight one (for example `ApiError.lock: "landed" | "pending"` next to `retryAfter`; the field name is the planner's). If both exist, the landed lock wins.

| Case | Copy |
|------|------|
| Landed lock | "{t} launched on BONDR {ago} ago. Try again in {wait}, or change the ticker in step 1. Nothing was sent." Example: "$PEPE launched on BONDR 3h ago. Try again in 21h, …" |
| In-flight lock | "Another launch of {t} is being signed on BONDR right now. Try again in a few minutes, or change the ticker in step 1. Nothing was sent." |
| `retryAfter` missing (Pitfall 24 guard) | "{t} launched on BONDR in the last 24 hours. Try again later, or change the ticker in step 1. Nothing was sent." |

Formatting (`retryAfter` is seconds):
- `{wait}`: at 3600 or more, whole hours rounded up, "21h". Under 3600, minutes rounded up with a minimum of 1: "25 minutes", "1 minute".
- `{ago}`: from `86400 - retryAfter`. At 3600 or more, whole hours rounded down ("3h"). Under 3600, minutes rounded down ("40 minutes"), and "less than a minute" at 0. Rounding the wait up and the age down keeps the two adding up to 24h.
- Numbers stay in the sentence's sans face. No `num` class inside a sentence (matches the existing fault lines).

Inline field error: none before submit, and no pre-check call (prepare is the only read, D-40). After a `ticker_locked` refusal, when the creator goes back to step 1, the symbol field shows the first two sentences only ("$PEPE launched on BONDR 3h ago. Try again in 21h.") through the existing `FieldError` (`components/launch-coin.tsx`). It clears as soon as the normalized symbol differs from the refused one. It is client state only and is not stored.

### A3. "First" marker in search results (D-44)

Shown only when a search `q` is present and two or more visible coins share the exact ticker `upper(trim(q))`. The worker or route returns `first: true` on the oldest of them, which is listed first among the exact matches (Pattern 12). A single exact match, a partial match, the unsearched list and Trending never show it. Rows added live by `mergePage` never carry it.

- Component: the existing `Tag tone="plain"` (neutral ledger tone). Not leaf, because it is a fact and not an endorsement (the accent list stays at 32 items). Not warn, because the later coins are not flagged as fakes.
- Placement: `components/coin-card.tsx`, in the name row right after the symbol, wrapped in `flex-none`, so the name truncates first and the Tag never wraps or shrinks.
- Accessible name: `<Tag tone="plain">First<span className="sr-only"> launched with this ticker</span></Tag>`. The card link reads "… PEPE First launched with this ticker …". No tooltip and no icon.
- 390 (card turns horizontal below 560px): same row. The name truncates and the symbol and Tag stay whole. 768 and 1440: same row, no change. The Tag can add up to 4px to the row height, which is accepted.
