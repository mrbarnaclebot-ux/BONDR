# packages/core/src

The shared chain library. Phase 1 spike scripts call it, and Phase 2 apps import the same modules.

- `pump.ts`: the only file that loads the pump SDKs (through createRequire). Web code must never import it.
- `net.ts`: `connect(net)` with genesis and host guards, and `redact()` for every outbound error.
- `keys.ts`: `derive(master, role, net, id)` HMAC key derivation.
- `config.ts`: reads the live pump Global, FeeConfig and AMM FeeConfig as JSON-safe facts.
- `send.ts`: the one send path: program allowlist (`checkMessage`), `budget`, `wireSize`, paced `sendTx` (= `signTx` + `sendRaw`); `signTx` compiles, checks and signs without sending, so the fee engine records its intent before broadcast (D-08); `sendRaw` sends an already signed wire with the same landed / failed / unknown semantics, and `broadcast` is its send-only first half (the worker settles launches itself).
- `float.ts`: `wFloat(conn, w, bytes)`, the lamports W needs to stay rent-exempt for the accounts it pays for, rents read live (devnet rent differs from the fork's). The spike wraps it.
- `trade-error.ts`: `fromLogs` and `customCode` (a failure's code from logs or meta.err, send.ts uses them too), `tradeError(err, logs)`, `textError(message)` and `launchError(err, logs)`, the maps from a simulation, preflight or on-chain failure to a contract code. Custom codes are keyed by the program that raised them, read from the logs (AMM 6004 / 6040 and pump 6002 / 6003 slippage, pump 6107 / 6005 and no tradable venue paused); low funds insufficient_balance, dead blockhash expired. A launch keeps only pump 6107 paused and low funds.
- `cosign.ts`: sign order A (D-12): `sameMessage` (raw byte compare), `slot`, `signatureOk` (re-exported from sig.ts), `exitPresent` (BurnChecked or multi_hop_swap in the message), `cosign` (adds the mint signature only when all pass). Worker-only: it loads pump.ts.
- `sig.ts`: `signatureOk`, the node:crypto Ed25519 check. No web3.js, so web's consent route can load it.
- `alt.ts`: per-coin lookup tables: `tableKeys`, `sharedKeys`, `createTable` with warm-up wait.
- `math.ts`: pure bigint amount math (`applyBps`, `split90_10`, `trigger105`, `minLamports` for the D-17 dev-buy minimum, `estimateSolBack` for the fee-only insta-sell estimate), no SDK import. Web may import it.
- `fees.ts`: the pure fee engine rules (`PUBLIC_KINDS`, `windowOf` / `windowEnd` from launch, `budgetOf`, `sweepSplit`, `minOutAfter` for WR-08, `deployerOk` for the D-18 pre-flight, `distributeMin`, `totalsFor` the per-kind coin totals map, `reconcileDiff`). Reuses math.ts, no SDK import. Web may import it.
- `rules.ts`: the launch field rules every tier runs (`checkName` in UTF-8 bytes, `checkSymbol`, `checkDescription`, `normalizeLink`, `imageType` / `checkImage` by magic bytes, `checkUri`, `parseSol`, `checkDevBuy`). Pure and import-free; returns codes, web owns the copy. Web may import it.
- `api.ts`: the web/worker contract (`Status`, `Quote`, `PrepareRequest`, `PrepareResult`, `SubmitResult`, `LaunchView`, `LaunchErrorCode`). Types only, no imports. Web may import it.
- `api-admin.ts`: the Phase 6 owner console contract (`AdminJob` switches, `AdminTxAction` / `AdminActAction` / `AdminAuditAction` matching migration 0007, `AdminHealth`, `AdminBalances`, `AdminSimResult` with its intent, `AdminIntentView`, `AdminInspect`, `AdminAuditRow`, `ModerationResult`). Types only, no imports. Web may import it.
- `launch.ts`: `buildCreate` and `buildLaunch` (create + exact-out dev buy + burn or sell, one tx). The SOL to BONDR hop and the sell's BONDR to SOL hop use BONDR's venue: its curve, or its PumpSwap pool once migrated (D-18). `quoteVenue` throws `AwaitingMigration` in the complete-but-unmigrated window; `launchQuote` prices a launch with no wallet; `minSolOut` floors the insta sell.
- `trade.ts`: v3 curve trades `buyExactIn`, `buyExactOut`, `sellExactIn`, each with the idempotent ATAs it needs; PumpSwap v2 `poolBuy` / `poolSell`, `poolState` (the one pool state fetch, pinned buyback wallet) and `poolBaseFor` (base out for a quote, fees included); `tokenDelta` and `lamportDelta`, the landed amounts from a tx meta.
- `collect.ts`: `collectIxs` (W's quote ATA, sweep unless `sweepCurve` is false, collect_creator_fee_v2) and `splitIxs` (10% to the treasury).
- `route.ts`: `routeBuy` / `routeSell`: multi_hop_swap through the SDK route resolver, simulated min out, and the venue of each hop (curve or pool).
- `quote.ts`: `routeQuote`, the wallet-free route quote: the SDK's `multiHopSwapQuote` with `curveHop` (pump v3 math charging only the fees the hop's legs name) for curve hops, the masked per-hop fee breakdown in SOL, price impact and the slippage floor; `curveRates` reads a curve's live rates. Worker-only: it loads pump.ts.
- `quote-read.ts`: `readConfigs` (pump Global and FeeConfig, AMM GlobalConfig and FeeConfig in one read), `readMintState` (a mint's venue, curve or pool state, supply and token programs in one read; the resolveMultiHopRoute venue rule, `awaiting` in the 6107 window) and `hopInputs`, the one builder of quote.ts HopInputs (worker and fork rows). Worker-only: it loads pump.ts.
- `quote.test.ts`: both hops of the devnet multihop fixtures to the base unit, the fee masks for both sides and all four venue pairs, impact, floor and the supply cap.
- `sharing.ts`: `finalizeConfigIxs` (sweeps, config) and `finalizeUpdateIxs` (sweep, the one 80/20 update), `finalizeIxs` (both, for the spike), `finalizeState` (complete, pool and sharing in one read), `updateIxs`, `readSharing`, `distributeIxs` (the SDK's sweeps, consolidation and distribute_creator_fees_v2, order untouched).
- `curve.ts`: `readCurve`, `costToComplete` (SDK v3 quote for the rest of a curve) and `costFromReserves`, the same quote over indexed reserves with no RPC (the D-10 trigger).
- `curve-state.ts`: `curveState`, a curve coin's patch from one TradeEvent (reserves, mcap, progress, `feesUnclaimed`, `bondrSol`), split from trades.ts.
- `bond.ts`: `forcedBondIxs` (simulated buy then BurnChecked), `exactBondIxs`, `migrateIxs`, `poolBuyBurnIxs`, `poolBaseOut`.
- `events.ts`: `innerEvents` (pump and PumpSwap events, each with its program and running `ix`) and `completeEvents`, from emit_cpi inner instructions under each program's event authority, never from logs.
- `price.ts`: pure indexer math: `SUPPLY` (fixed 1B, D-22), `curvePrice`, `poolPrice`, `toSol`, `mcapSol`, `progress`, `bondrAtBond`. No SDK import. Worker-only for now; web reads the stored values.
- `trades.ts`: `parseTx(tx, coins, bondr, launch?)`, the pure parser every indexer path shares: one fetched tx to trade rows (launch rows and the synthetic burn row, D-16), coin patches, the new coin in launch mode, BONDR's same-tx price, and unused event names. Only known coins or the launch mint produce rows (D-03). Worker-only.
- `scrub.ts`: `scrub` (every 32-44 char base58 run becomes `[addr]` in a Sentry event or breadcrumb, D-19) and `forbiddenEnv` (the seed, Helius key, Sentry auth and read tokens and staging URL names web refuses to boot with, FEE-10) and `dataCollection` (the restrictive Sentry v11 options all three SDK inits share). Pure and import-free. Web may import it.
- `schema.ts`: the Postgres tables (wallets, settings, vanity_mints, launches, coins, trades, fee_ledger) with their CHECK constraints, the landed-mint unique index and the fee_ledger partial unique indexes that refuse a double intent (D-08); the Phase 6 job switches on settings and the hide and hold columns on coins. Web may import it.
- `schema-admin.ts`: the Phase 6 admin tables, re-exported by schema.ts: `blocked_deployers` (D-30) and the append-only `admin_audit` (D-33; its `admin_audit_guard` trigger is hand-written in migration 0007). `db-admin.test.ts` proves them, each case in a rolled-back transaction.
- `db.ts`: `db()` lazy drizzle singleton over postgres.js (idle_timeout so Neon scales to zero) and `close()`; re-exports the schema. Web may import it.
- `migrate.ts`: the only migration runner (`pnpm db:migrate`), under `pg_advisory_lock`; reads `../migrations`, generated by `pnpm db:generate`.
- `fixtures/`: captured transactions for the event and parser tests (public chain data), written by `scripts/capture-tx.ts` as `{ capturedAt, mint, net, response, slot, source }` with the raw `getTransaction` JSON. Devnet (03-01): `launch-burn` (create, dev buy, burn; BONDR loaded from the per-coin lookup table), `launch-sell` (create, dev buy, multi-hop sell to SOL; table-loaded), `curve-buy` / `curve-sell` (a child's v3 curve trade paid in BONDR), `multihop-buy` / `multihop-sell` (SOL to BONDR to child and back, two TradeEvents), `bondr-buy` (a BONDR-only buy on BONDR's curve). Fork (03-01, net "fork", from the spike run; a devnet child needs more BONDR than BONDR's curve holds, so A8 failed): `complete` (forced-bond buy: TradeEvent, CompleteEvent, PostCompleteBuyEvent), `create-pool` (migrate_v2: CompletePumpAmmMigrationEvent, PumpSwap CreatePoolEvent), `pool-buy` / `pool-sell` (a child's PumpSwap buy_v2 / sell_v2 in BONDR: BuyEvent, SellEvent).
- `*.test.ts`: vitest checks for the pure parts.

ponytail: core exports raw `.ts` and relies on Node type stripping (D-15). Next.js needs `transpilePackages`, and the Railway worker must run from the workspace checkout: `pnpm deploy` or an injected install would put core under `node_modules`, where Node refuses to strip types. Upgrade path: a build step for core.
